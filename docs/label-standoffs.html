Marker Label Standoffs

All eight compass positions, drawn at the exact world-unit offsets labelPlacement() produces. Every label's icon-facing edge lands on the gap boundary at extent + gap: baseline for top labels, cap top for bottom, and the right / left glyph edge for left / right (text-anchor: end / start). All positions use dominant-baseline: alphabetic; left / right add a y = capHeight/2 offset so the caps' vertical center sits on the icon's y-axis.

Reading the diagram

  • Dashed square — the icon's bounding box (side = ICON_SIZE). All standoffs are measured from this edge.
  • Amber line + dot — the standoff (icon edge → gap boundary at extent + gap). Every label's icon-facing edge lands on the dot: baseline for top labels (caps sit above), cap top for bottom labels (text sits below), right / left glyph edge for left / right labels (rest of the label extends outward). Left / right also offset y by capHeight/2 so the caps' visual center sits on the icon's y-axis.
  • Mobile's viewBox is 2× desktop's (7.2 × 7.2 vs 3.6 × 3.6 world units) because mobile's icon and font-size are both 2× — sharing a viewBox would clip the mobile panel. Each panel's 0.5-unit scale bar shows the real per-panel scale at a glance: mobile's bar is half the visible length of desktop's, correctly reading as "mobile's world unit is half as many pixels wide because there's twice as much content in the same panel."
  • Cap-height constant is EB Garamond's sCapHeight / unitsPerEm = 650 / 1000 = 0.65. Change the label font and this constant needs to change with it — the app's EB_GARAMOND_CAP_HEIGHT is where it lives.
